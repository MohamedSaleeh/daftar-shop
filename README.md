# دفتر المحل الرقمي

نموذج تفاعلي عربي RTL، مبني بـ React + TypeScript + Vite + Tailwind CSS + Lucide.
كل البيانات محلية في المتصفح؛ لا API خارجي ولا Backend ولا دفع أو مزامنة حقيقية.

## التشغيل

يتطلب Node.js 20.19+ أو 22.12+ و npm.

```bash
npm install
npm run dev
```

افتح العنوان الذي يظهر في الطرفية. لإنشاء نسخة إنتاج واختبار المنطق:

```bash
npm test
npm run build
```

## البداية

اختر «ابدأ» لإنشاء محل جديد دون تجهيز الأصناف، أو «جرّب ببيانات جاهزة أولًا».
تحميل البيانات التجريبية وإعادة الضبط ومحاكاة الخطط متاحة في الإعدادات.

## المسارات المنفذة

- إعداد المحل والعملة وأرصدة صندوق افتتاحية اختيارية.
- بيع متعدد الأصناف، إضافة صنف وزبون داخل البيع، تعديل السعر والكمية والخصم.
- دفع كامل أو جزئي أو آجل، مع اختيار الحساب عند وجود دين.
- ثلاث عملات مستقلة، دفع وتحصيل بعملة مختلفة وسعر صرف يدوي محفوظ.
- مخزون اختياري يبدأ من الكمية الحالية؛ لا إعادة احتساب للمبيعات السابقة.
- خصائص حتى اثنتين، مع فصل مخزون كل تركيبة فعلية.
- كميات عشرية ووحدات وزن وحجم وتعبئة بمعامل تحويل؛ لا تحويل وزن إلى حجم.
- شراء بضاعة، دفعة جزئية للمورد، كشف حساب ودفعات لاحقة.
- مرتجع جزئي أو كامل مرتبط بالبيع، إعادة للمخزون أو تالف، رد نقدي أو تخفيض الدين.
- إلغاء مع عكس الأثر وحفظ العملية وتاريخها؛ لا حذف للفواتير المؤكدة.
- مصاريف، إضافات وسحوبات صندوق، وإغلاق مستقل لا يغيّر السجل.
- أرشفة صور فواتير منفصلة بلا أثر مالي؛ إرفاق صورة بالشراء.
- تقارير وفلاتر وبحث عام، ربح تقديري مع نسبة تغطية التكلفة.
- تنزيل واستعادة JSON مع فحص البنية وتأكيد الاستبدال.
- Trial / Local / Cloud / Read Only ومحاكاة انتهاء السحابة مع استمرار المحلي.

## معمارية الكود

- `src/domain/model.ts`: الأنواع، UUIDs، أرصدة الحسابات والصندوق.
- `src/domain/operations.ts`: العمليات والتحقق وعكس الأثر.
- `src/domain/backup.ts`: التحقق من النسخ الاحتياطية.
- `src/domain/seed.ts`: بيانات عربية جاهزة.
- `src/state/store.tsx`: React Context وحفظ localStorage.
- `src/components/ui.tsx`: عناصر الواجهة المشتركة.
- `src/features/`: المبيعات والأصناف والحسابات والصندوق والتقارير والإعدادات.

تُطبّق العمليات المركبة على نسخة مستقلة من الحالة. لا تتغير الحالة الأصلية إذا فشل التحقق، وتُكتب الحالة كاملة في localStorage قبل عرض النجاح.
المفتاح المحلي: `daftar-shop-v1`. التواريخ ISO، والعرض بتوقيت جهاز المستخدم.

## قواعد وتفاصيل النموذج

- أرصدة البداية والتحصيل والسحب الشخصي لا تُحتسب مبيعات.
- دفعات المورد لا تُحتسب مصاريف تشغيلية.
- الدفعات على الحساب توزّع على الفواتير الأقدم المفتوحة بعملتها؛ الزيادة يمكن حفظها كرصيد أو ردها.
- النقدي والآجل في لوحة اليوم يشيران إلى الحالة وقت البيع، بينما شاشة الفاتورة تعرض الدفعات اللاحقة أيضًا.
- التقارير المرتبطة بفترة بيع تعرض تلك الفواتير بعد مرتجعاتها المسجلة، وليست قوائم محاسبية لإقفال فترات تاريخية.
- المرتجع النقدي يرد بعملة الفاتورة (موضح في الواجهة). عكس الإلغاء يعيد مبالغ الدفع بعملاتها الأصلية.
- تكلفة الشراء موزعة بعد الخصم، والمتوسط المرجح يُحسب إذا كانت تكلفة الكمية السابقة معروفة وبنفس العملة. وإلا تظهر التكلفة غير معروفة.
- عند إلغاء شراء، يعكس النموذج الكميات والدين والصندوق ويجعل التكلفة الحالية غير معروفة بدل اختراع متوسط جديد بعد حركات لاحقة.
- الصور أقل من 1 ميغابايت للصورة، وتدخل ضمن نسخة JSON. مساحة localStorage محدودة؛ فشل التخزين لا يُعلن نجاح العملية.
- العمل دون اتصال والقفل والسحابة والترخيص محاكاة لا حماية أو مزامنة حقيقية. العمليات المحلية لا تستدعي الشبكة؛ تحميل الصفحة لأول مرة يحتاج خادم التطبيق، ولا يوجد Service Worker لإعادة فتح نسخة مستضافة دون شبكة.
- استخدم تبويبًا واحدًا للتحرير؛ لا يوجد تنسيق كتابة متزامنة بين عدة تبويبات أو أجهزة.
- Reset وتحميل Seed يستبدلان البيانات بعد التأكيد. نزّل نسخة احتياطية أولًا.

## التحقق المنفذ

12 اختبارًا آليًا للعمليات: المخزون غير المتابع وبداية المتابعة، الدفع الجزئي والتحصيل، سعر الصرف، تحويل التعبئة، المرتجعات والخصم والإلغاء، الزيادة كرصيد، فشل العملية الذري، القراءة فقط، تحذير المخزون السالب، استقلال التركيبات، المتوسط المرجح، واستعادة النسخة والتحقق منها.

فحص واجهة المتصفح: تحميل Seed، بيع جزئي وتحديث الملخص، استمرار البيانات بعد إعادة التحميل، إضافة صنف أثناء البيع وبيعه مباشرة، معاينة لوحة التحكم ونافذة البيع بعرضي 360 و390 بكسل.
